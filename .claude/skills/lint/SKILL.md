# lint

`tools/hel.py check` では見つけられない、意味の上での問題を点検して直します。最後に Pull Request を作ります。

規則の詳細はリポジトリ直下の `CLAUDE.md` に従います。作業の前に必ず読んでください。

## してはいけないこと

- **新規素材を作らない。** 足りない素材を見つけたら、GitHub Issue に提案を起票します。
- 既存素材を分割・移動して再配置するのは新規追加に当たりません。行ってかまいません。

## 点検項目

1. **機械的な検査**: `uv run tools/hel.py check` を実行し、エラーがあれば直します。
2. **方針の矛盾**: 素材どうしで方針が食い違っていないか。例: 原則では「インデントは 2 spaces」なのに、Formatter の素材の設定が 4 spaces になっている。
3. **依存の漏れ**: 他の素材の方針に合わせて書いているのに `depends_on` がない素材はないか。逆に、もう依存していない `depends_on` は残っていないか。
4. **ディレクトリ構成**: 1 つのディレクトリに性質の違う素材が混ざっていないか。例: `middleware/` を `database/` と `queue/` に分ける。
5. **粒度**: 1 つの素材に複数の要素が入っていないか。逆に、小さすぎて親の素材に吸収すべきものはないか。
6. **タグ**: 付け漏れや、意味が重なるタグはないか。
7. **レイヤー間の重複**: 下位レイヤーの素材の内容が上位レイヤーに取り込まれていて、削除できるものはないか。
8. **古さ**: `verified_at` が古い素材を一覧にし、`/refresh` の対象として報告します。

## 手順

1. 点検結果を一覧にして人間に提示し、どれを直すか確認します。
2. ブランチを作ります: `lint/<要旨>`
3. 直します。
   - 再配置で論理 ID が変わったら、全レイヤーの `depends_on` と本文リンクを同じ PR で直します。
   - 方針が変わった素材は、履歴節に追記し、`updated` と `models` を更新します。
   - 本文を書き換えたときは、その部分を `yomiyasu` スキルで推敲します。
4. 検査します。

   ```sh
   uv run tools/hel.py index
   uv run tools/hel.py check
   ```

5. PR を作ります。
   - タイトル例: `lint: middleware/ を database/ と queue/ に分割`
   - 本文には、見つけた問題、直した内容、起票した Issue のリンクを書きます。
