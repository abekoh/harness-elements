# refresh

既存素材の内容が今も正しいかを確かめ、必要なら更新します。最後に Pull Request を作ります。

規則の詳細はリポジトリ直下の `CLAUDE.md` に従います。作業の前に必ず読んでください。

## してはいけないこと

- **新規素材を作らない。** 新しい素材が必要だと判断したら、GitHub Issue に提案を起票します。Issue には、素材の論理 ID 案、必要な理由、参考になる公開資料を書きます。
- 根拠のない stance 変更をしない。stance を変えるときは、公式発表などの公開ソースを根拠にします。

## 手順

1. **対象を決める**
   - 人間が指定した素材、または次の条件に当てはまる素材を対象にします。
     - `version` があり、対象の新しいメジャーバージョンが出ている
     - `verified_at` から 6 か月以上たっている
   - 対象が多いときは、一覧を人間に見せて優先順位を確認します。

2. **最新情報を調べる**
   - 公式ドキュメント、リリースノート、移行ガイドを優先して読みます。
   - 素材の「方針」と「トレードオフ」に影響する変更があるかを判断します。
   - `version` を持つ素材は、メンテナンス状況(メンテナ、スター数、最新コミット、最新リリース、アーカイブの有無)も調べ直します。

3. **ブランチを作る**: `refresh/<要旨>`

4. **更新する**
   - 影響がなければ `verified_at`(と `version`)と、解説節の「メンテナンス状況」の表だけを更新します。履歴節には書きません。
   - 影響があれば本文を直します。stance、方針、対応バージョンが変わった場合は履歴節に 1 行追記します。
   - `updated` を今日の日付にし、`models` に自分のモデル ID がなければ追記します。
   - この素材を `depends_on` で参照している素材(下位レイヤーを含む)に影響が出ないかを確かめ、必要なら同じ PR で直します。

5. **推敲する**: 本文を書き換えたときは、その部分を `yomiyasu` スキルで推敲します。

6. **検査する**

   ```sh
   uv run tools/hel.py index
   uv run tools/hel.py check
   ```

7. **PR を作る**
   - タイトル例: `refresh: Go 1.26 に追従`
   - 本文には、根拠にした公開ソース、変更点、stance を変えた場合はその理由を書きます。
