# yomiyasu

## 概要

yomiyasu(よみやす)は、AI が書いた日本語を推敲する Agent Skill です。技術記事、設計書、仕様書、PR の説明文、社内レポートなど、実務の文章を主な対象にしています。

AI が書いた日本語には、「静かに壊れる」「効く」のような比喩の動詞、主語と述語のずれ、道具や概念を擬人化した言い方、太字や箇条書きの多用が残りがちです。禁止語を並べるだけの対処では別の曖昧な語に置き換わるだけで、文の構造は直りません。yomiyasu は主張、比重、言い切りの強さ、文の働きを変えないことを最優先にして、読み違えやすい箇所だけを直します。直したあとは付属のスクリプトで原文と最終稿の差分を検査し、情報を足したり削ったりしていないかを確かめます。

## 方針

2026 年 9 月に公開されたばかりで、1 か月で 26 回リリースされるほど規則の変更が多いため trial とします。

- 日本語の文書を書いたあと、推敲の段階で yomiyasu を使う。
- 書く段階の規範(japanese-tech-writing など)と併用する場合は、役割を分ける。書く段階はそれらの規範、書き上げた文の推敲は yomiyasu とする。指示が食い違って出力が乱れたら、片方を外して比べる。
- 毎回使わせたいときは、CLAUDE.md や AGENTS.md に 1 行で指示する。スキルの名前は導入の方法で変わる(下記)ので、実際の名前で書く。
- 検査の記録が作業フォルダの `.yomiyasu/` に残るため、`.gitignore` に `.yomiyasu/` を足す。
- 規則の変更が多いので、更新を取り込んだら推敲の結果を見直す。

## 解説

### 推敲の原則

yomiyasu は次の 7 つの原則で推敲します。

1. 主語と述語、修飾語と掛かる先、指示語と指す対象を対応づけ、条件や否定、並列が書き直す前後で同じに追えるかを確かめる。
2. 文ごとに説明・依頼・助言・予定を区別し、働きに合わない文末だけを直す。常体・敬体は指定がなければ保つ。
3. 道具や概念に感情や意志を持たせた擬人化を直す。道具の客観的な動作を述べる文は残す。
4. 「壊れる」「倒す」「効く」「溶かす」などの比喩の動詞を、含みや意味の広さを保って言い換える。
5. 前置きや否定対比(A ではなく B)は、削っても主張が変わらないときだけ削る。
6. 原文にない主体、原因、条件、数値などを足さない。意味を決められない箇所は本文に残し、書き手に確かめる点として報告する。
7. 平均の文長(30〜45 字)、1 文の読点(0〜2 個)を目安に、間を作るだけの読点や過剰な装飾を整理する。

### 仕組み

スキルの本体(`SKILL.md`)に加えて、参照文書と Python の検査スクリプトが付いています。

- `yomiyasu_lint.py`: 比喩の動詞、AI がよく使う語、間を作るだけの読点、太字の多用などの候補を出す。
- `yomiyasu_check.py run`: 最終稿の lint と、原文と最終稿の差分の検査をまとめて実行する。差分の検査は消えた語、元にない語、文末の種類の変化(依頼が説明に変わった、など)を候補として出す。
- `yomiyasu_check.py verify`: 提出する文が検査した最終稿と同じかをハッシュで確かめる。

検査の結果は合否ではなく、見直す候補です。推敲の結果は「書き直した本文」「変えたところ」「書き手に確かめたい点」などの決まった形式で返します。

### 導入

Claude Code ではスキルとして入れるか、プラグインとして入れます。

```sh
npx skills add nanaism/yomiyasu          # スキルとして入れる。名前は yomiyasu
gh skill install nanaism/yomiyasu yomiyasu
```

```text
/plugin marketplace add nanaism/yomiyasu
/plugin install yomiyasu@yomiyasu        # プラグインとして入れる。名前は yomiyasu:yomiyasu
```

Codex では、どの入れ方でも名前は `yomiyasu:yomiyasu` です。スキルの大きさに上限がある環境向けに、短くした yomiyasu-mini(SKILL.md が 18,000 字以下)と、指示欄に貼る 400〜500 字の yomiyasu-pocket も公開されています。

### 使い方

名前を出して頼んだときだけ使われます。名前を出さずに「読みやすくして」とだけ頼むと、エージェントは yomiyasu を使いません。

```text
この文章を yomiyasu で読みやすくして。
```

毎回使わせたいときは、CLAUDE.md などに次のような 1 行を書きます。

```text
記事、ドキュメント、PR の説明文、コミットメッセージなどの日本語の文章を書いたり直したりするときは、常に yomiyasu スキルで推敲してください。
```

## トレードオフ

### 得られるもの

- 比喩の動詞、擬人化、主述のずれなど、AI の日本語に残りがちな癖が減る。
- 意味を変えないことを優先するため、推敲で主張や条件が変わりにくい。
- 差分の検査で、情報を足したり削ったりしていないかを確かめられる。

### 失われるもの

- 規則が長く、推敲のたびにコンテキストと時間を多く使う。検査には Python が要る。
- ほかの日本語のスキルと指示が食い違うことがある。
- 規則の変更が多く、更新のたびに出力が変わりうる。
- 名前を出さないと使われないため、毎回使わせるには指示の 1 行が要る。

## 採用すべき？

### 採用すべきケース

- AI が書いた日本語の記事、仕様書、PR の説明などを、公開や共有の前に推敲したい。
- 推敲で意味が変わっていないかを、差分で確かめたい。

### 採用すべきでないケース

- 推敲のたびに時間がかかるのを許容できない、短いやりとりが中心の作業。
- 組織の文章規範がすでにあり、指示が食い違う。
- 出力の安定を重視し、規則の頻繁な変更を避けたい。
