# モックは管理外の依存にだけ使う

## 概要

モックを使うのは、外部 API やメール送信のように、自分たちの制御下にない依存(管理外の依存)への出力を検証するときだけにします。テストの古典学派の考え方です。

## 方針

モックの使いすぎによる壊れやすいテストを避けるため adopt とします。

- [モック](mock-vs-stub.md)を使うのは、外部 API、メール送信、メッセージの送信など、管理外の依存への出力に限る。
- DB のように自分たちだけが使う依存(管理下の依存)は、モックにせず本物を使って統合テストで検証する。
- テスト対象の内部にあるクラスや関数どうしの呼び出しは、モックにしない。

## 解説

管理外の依存への出力は、外から観測できる振る舞いの一部です。外部 API との約束(呼び出し方)は後方互換を保つ必要があるため、モックで検証する価値があります。

一方、管理下の依存やシステム内部の通信は実装の詳細です。モックで検証すると、リファクタリングのたびにテストが壊れます。

テストの流派には、古典学派(デトロイト学派)とロンドン学派があります。ロンドン学派はテスト対象以外のほぼすべての依存をモックにします。

## トレードオフ

### 得られるもの

- テストがリファクタリングで壊れにくい。
- 本物の DB を使うため、SQL や制約の誤りも検出できる。

### 失われるもの

- 本物の DB を用意するため、テストの準備と実行に時間がかかる。
- ロンドン学派に比べ、失敗したときに原因の箇所を特定しにくい。

## 採用すべき？

### 採用すべきケース

- テスト用の DB をコンテナなどで手軽に用意できる。

### 採用すべきでないケース

- 本物の DB をテストで使えない環境で、DB アクセスもモックで代替するしかない。
